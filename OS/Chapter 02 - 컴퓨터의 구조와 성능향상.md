# 컴퓨터의 기본 구성
- 필수장치: 중앙처리 장치(CPU), 메인 메모리
- 주변장치: 입력장치, 출력장치, 저장장치

## 하드웨어
- CPU: 명령어 해석 후 실행
- 메인 메모리: 작업에 필요한 프로그램의 코드와 데이터를 저장하는 휘발성 저장 장치
- 저장 장치: 반영구적으로 데이터를 저장하는 비휘발성 저장 장치
- 메인보드: 데이터가 지나는 버스를 제공하여 하드웨어끼리 데이터 전송 및 연결

## 폰노이만 구조
- 하드웨어를 변경하지 않고, 명령어와 데이터를 같은 메모리에 저장해 두고 CPU가 메모리에서 명령어를 순서대로 읽어 실행하는 범용 컴퓨터 구조.
	- 이전의 컴퓨터는 다른 작업을 하기 위해서는 물리적 배선을 변경하여야 했음
		- 하드웨어로 프로그램을 구성하였음
	- 프로그램을 데이터처럼 다룸

- 모든 프로그램은 메모리에 올라와야 실행할 수 있다.

## 기초 용어
#### 크기 단위
- 바이트 - 킬로바이트 - 메가바이트 - 기가바이트 - 테라바이트 - 페타바이트
- 이전 단위의 2^10배씩 커짐
#### 클럭
- 회로마다 다른 신호 지연을 가짐 -> 언제 계산이 끝나는지 알아야 함 -> 모든 회로가 박자에 맞춰 값을 확정하고 다음 단계로 넘어가게 하는 기준 신호.
- 폰노이만 구조에서는 인출 - 해석 - 실행 단계를 거치기 때문에 다음 단계로 값을 전달해야함
	- 하지만 회로마다 지연이 달라지면 언제 값이 넘어가야하는지 모름

#### 시스템 버스와 CPU 버스
- 시스템 버스: 메모리와 주변장치를 연결하는 버스
	- FSB(Front Side Bus)라고도 함
- CPU 버스: CPU와 내부의 여러 장치를 연결하는 버스
	- BSB(Back Side Bus)라고도 함
#### 프로그래밍과 언어
- 저급 언어 - 기계어에 가까운 언어
	- 기계어 - 0과 1로 이루어진 컴퓨터가 이해하는 언어
	- 어셈블리어 - 기계어를 문자 형태로 변경한 것
- 고급 언어 - 사람에게 가까운 언어
	- 고급 언어 -> 컴파일러(컴파일) -> 기계어

## 필수 자료 구조
- 큐: 먼저 들어온 자료가 먼저 처리되는 자료 구조(FIFO)
- 스택: 먼저 들어온 자료가 마지막에 처리되는 자료 구조 (FILO)
- 배열: 같은 형태의 자료를 메모리에 연속으로 저장하는 것
- 연결 리스트: 메모리에 비연속적으로 저장하고 자료가 다음 자료의 위치 정보를 가지고 있는 자료구조

### CPU의 명령어 처리 과정
### 레지스터의 종류
- 데이터 레지스터 (DR: data register)
	- 데이터를 담는 레지스터
	- ALU의 입력으로 실제 연산에 참여하는 데이터를 저장함
- 주소 레지스터 (AR: address register)
	- 메모리에 접근할 주소를 저장함
	- e.g. MAR(Memory Address Register)
- 프로그램 카운터 (PC: program counter)
	- 다음에 실행할 명령어의 주소를 저장함
- 명령어 레지스터 (IR: instruction register)
	- 메모리에서 읽은 명령어를 저장함
### 버스의 종류
- 제어 버스
	- 제어신호를 전달하는 버스
	- CPU, 메모리, 주변장치와 양방향 통신
- 주소 버스
	- 주소가 이동하는 버스
	- MAR -> 메모리로 단방향 통신
- 데이터 버스
	- 데이터가 이동하는 버스
	- MBR <-> 메모리로 양방향 통신
### CPU 비트의 의미
- CPU가 한 번에 처리하는 데이터의 크기인 워드(word) 길이를 의미
## 메모리의 종류와 부팅
### 메모리의 종류
- RAM(Random Access Memory)
	- 읽기 쓰기가 가능한 메모리
	- 휘발성: 전력이 끊어지면 데이터가 사라지는 성질을 가진 메모리
	- 비휘발성: 전력과 무관하게 데이터를 저장하는 성질을 가진 메모리
- ROM (Read Only Memory)

#### 휘발성 메모리
- DRAM(Dynamic RAM)
	- 시간이 지나면 데이터가 사라짐
		- 따라서 주기적으로 고립된 캐퍼시터에 전력을 공급하여 재생시켜야함 (주로 64ms마다)
	- DDR(Double Data Rate): 한 클록에 2개의 워드를 전송함
- SRAM(Static RAM)
	- 전력이 공급되는 동안 데이터를 보관할 수 있다.
		- 플립플롭이 회로와 연결되어 있어 전력이 공급되면 데이터는 사라지지 않음
- SDRAM(Synchronous Dynamic RAM)
	- 클럭과 동기화되어 동작하는 DRAM
		- 기존 DRAM은 클럭과 별개로 동작하기 때문에 CPU가 언제 데이터를 받을 수 있을지 모르고 기다리는 문제를 해결

#### 비휘발성 메모리
- 전력이 없어도 데이터를 보관하는 저장장치
- 하지만 최대 사용횟수가 제한되어 있음
- 종류
	- 플래시 메모리
	- FRAM(Ferroelectric RAM)
	- PRAM(Phase change RAM)

#### ROM 종류
- mask ROM
	- 칩 생산 과정에서 데이터를 회로에 고정함
- PROM(Programmable ROM)
	- 빈 상태로 제조된 칩에 사용자가 전용 기록 장치를 이용하여 데이터를 기록
	- 주로 퓨즈를 끊어 버리는 방식으로 영구 저장
- EPROM(Erasable Programmable ROM)
	- 전기적으로 데이터를 기록하고 자외선이나 전기적으로 데이터를 지울 수 있다.

> [!note]+ 바이오스는 ROM에 저장되는거 아닌가?
> - 과거의 마더보드는 바이오스를 ROM에 저장함
> - 요즘에는 바이오스 업데이트를 지속적으로 지원하기 위해서 플래시 메모리로 변경됨

### 메모리 보호
- 메모리는 사용자 영역과 운영체제 영역으로 구분되어 있다
- 사용자 영역 또한 각 프로그램마다 작업 공간이 분리되어 있다.
- 이유
	- 작업이 다른 작업에 영향을 미치는 것을 막기 위해서
		- 바이러스등
- 방법
	- 경계 레지스터와 한계 레지스터에 작업 공간의 시작과 끝 주소를 저장하고 넘어가지 못하도록 하드웨어적으로 방어함
	- 침범시 인터럽트를 발생시킴

### 부팅
- 운영체제를 실행하여 컴퓨터를 실행 가능한 상태로 만드는 준비 과정
- BIOS(Basic Input/Output System)
	- 컴퓨터
- MBR(Master Boot Record)
	- 부팅 코드와 디스크 파티션 정보를 가짐
	- 디스크의 첫 번째 섹터에 저장함

- 과정
	1. BIOS 실행
	    - 하드웨어 초기화·점검
	    - 부팅할 디스크 선택
	    - 디스크의 MBR을 RAM으로 읽고, 그 안의 부트스트랩 코드로 실행을 넘김
	2. MBR의 부트스트랩 코드 실행
	    - 다음 단계의 부팅 코드를 불러와 실행
	3. 후속 부트로더 실행
	    - 디스크에 저장된 운영체제 커널을 RAM에 올림
	    - 커널로 실행을 넘김
	4. 운영체제 실행
	    - 드라이버와 서비스를 초기화하고 사용 가능한 상태로 준비
# 컴퓨터 성능 향상 기술
## 버퍼
- 두 장치 사이의 속도 차이를 완화하는 역할
- 대량의 데이터를 일시적으로 보관하여 속도 차이를 완화
- 예를 들어:
	- 보내는 속도: 초당 100MB
	- 처리하는 속도: 초당 60MB
	- 버퍼에 쌓이는 양: 초당 40MB
### SPOOL(Simultaneous Peripheral Operation On-Line)
- CPU와 입출력 장치가 독립적으로 동작하도록 하는 소프트웨어적 버퍼의 일종
- 입출력으로 인한 대기 시간을 줄이기 위해서 대기 큐를 관리하는 프로그램
### 캐시
- 메모리와 CPU간의 속도 차이를 완화하기 위해서 데이터를 미리 가져와 저장하는 임시 저장소
- 메모리의 지역성을 이용하여 속도차이를 완화
	- 하지만 쓰기 작업시 메모리의 데이터와 불일치가 발생할 수 있음
		- 즉시 쓰기: 캐시의 데이터가 변경되면 즉시 메모리에 반영 => 속도 차이 발생
		- 지연 쓰기: 내용을 모아서 주기적으로 메모리에 반영 => 데이터 불일치 발생
- CPU에 여러 개 캐시를 단계적으로 두어 속도 차이를 완화시킴
	- CPU -> L1 () -> L2 -> L3 -> 주기억장치
	- 레벨이 높을수록 속도가 느리고 저장 크기가 커짐
	- L1은 명령어와 데이터를 구분하지만 L2, L3는 구분하여 저장하지 않음

## 인터럽트
- 문제: 기존에는 CPU가 입출력 장치의 상태를 알기 위해서 주기적으로 검사해야 했음 => CPU의 작업 효율이 떨어짐

- 입출력이 진행되는 동안 CPU가 다른 작업을 할 수 있도록 입출력 관리자를 통해서 장치가 완료 신호를 전달하도록 함
### 인터럽트 동작 
1. CPU가 장치 컨트롤러에게 입출력 명령을 전달
2. 명령에 따라 데이터를 이동시킴
3. 데이터 전송이 완료되면 CPU에 인터럽트 요청(IRQ: Interrupt ReQuest)을 전달함

- 여러 장치를 구별하기 위해서 각 장치마다 인터럽트 번호(interrupt number)가 부여됨
- 인터럽트는 동시에 여러 개가 발생하므로 벡터를 사용하여 전달한다.
## 직접 메모리 접근(DMA: Direct Memory Access)
- **문제:** CPU가 입출력 데이터를 하나씩 읽고 메모리에 쓰면, 데이터 전송에 CPU 시간을 사용하게 됨.
- **기능:** CPU가 데이터를 일일이 옮기지 않고도 입출력 장치와 RAM 사이에서 데이터를 전송할 수 있게 함.
    - **CPU:** 전송 위치·크기 등을 설정하고 전송을 지시.
    - **DMA 컨트롤러 또는 장치의 DMA 기능:** 실제 데이터 전송 수행.
    - **전송 완료:** 보통 인터럽트로 CPU에 알림.
## 메모리맵 입출력 (MMIO: Memory Mapped Input Output)
- 문제: CPU가 입출력 장치의 상태를 읽기 위해서 전용 입출력 명령과 버스 신호가 필요
- 기능: 입출력 장치마다 전용 메모리 주소를 할당하여 입출력에 사용함
	- 일반적인 메모리 읽기, 쓰기를 사용하여 단순해짐
## 사이클 훔치기
- CPU와 DMA가 동시에 메모리에 접근할 때 같은 메모리 버스를 사용하기 때문에 CPU가 한 버스 사이클을 양보하는 것
- 입출력 장치는 버퍼가 차면 데이터가 손실될 수 있음
# 멀티프로세싱
## 멀티코어 시스템
- 하나의 칩안에 독립적으로 명령어를 실행하는 코어를 여러 개 넣은 구조

- 레지스터의 개수를 늘려서 여러 쓰레드의 상태를 저장하지만 연산 장치는 하나라서 돌려씀
	- 한 쓰레드가 멈추면 다른 쓰레드의 작업을 바로 실행
