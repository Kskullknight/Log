# 프로세스의 개요
## 프로세스의 개념
- 프로그램: 보조 기억 장치에 저장된 명령어와 데이터의 집합
	- 실행 불가능한 정적 상태
- 프로세스: 메인 메모리에 적재되어 자신만의 코드, 데이터, 힙, 스택 영역을 할당받고 OS가 관리할 수 있는 상태
	- 실행 가능한 동적 상태
## 프로세스 동작 방식
### 일괄 작업 방식
- 작업할 프로세스를 하나의 큐에 넣어서 순차적으로 작업하는 방식
### 시분할 작업 방식
- 각 프로세스에 일정한 시간을 할당하고 할당된 시간만큼 작업하고 다른 작업으로 변경하여 여러 개의 프로세스를 처리하는 시스템

#### 시분할 방식의 문제점
- CPU 대기의 문제
	- 다른 장치의 결과를 기다리며 CPU 점유하면서 사용하지 않는 상황
- 작업 스위칭 문제
	- 작업을 바뀌기 위해서 드는 비용이 존재함
## 프로그램 -> 프로세스
- 보조 기억장치에 있는 프로그램은 주 기억장치에 할당함
- 프로세스에 대한 정보를 가진 프로세스 제어 블록(PCB: Process Control Block)을 만듦
	- 프로세스 구분자
	- 메모리 관련 정보
		- 프로세스가 사용하는 메모리의 위치 정보
	- 각종 중간값
		- 프로세스 중단이후 이어가기 위한 종료전 CPU의 상태값
- PCB는 운영체제 영역에 만들어서 운영체제가 관리함
- 프로세스 종료시 메모리 영역을 해제하고 PCB를 삭제함
- 운영체제도 부트스트랩에 의해서 실행되는 프로세스이다

## 프로세스의 상태
- 일괄 작업 시스템은 생성 - 실행 - 완료로 이루어짐
	- 작업이 생성되면 CPU를 얻은 후 작업을 마치면 종료되면 그만임
### 시분할 작업의 상태
- 실행 중 다른 프로세스로 넘어가야 하기 때문에 더 복잡한 상태를 가진다
#### 네 가지 상태
- 생성: 메모리에 올라와 실행 준비를 완료한 상태
	- PCB 생성됨
- 준비: 프로세스가 CPU를 얻을 때까지 대기하는 상태
	- 어떤 프로세스를 실행상태로 변경할지 스케쥴러에 의해서 결정됨
- 실행: CPU를 할당 받아 실제 작업을 수행하는 상태
	- 할당 받은 타임 슬라이스동안만 CPU를 점유할 수 있음
	- 작업을 완료하지 못하면 준비상태로 돌아가 대기함
- 완료:작업을 마치고 완료한 상태
	- PCB가 사라진 상태

- 문제점
	- 입출력 때문에 CPU를 사용하지 않아도 CPU를 점유하고 타임 슬라이스를 사용하여 비효율적임
### 다섯 가지 상태
- 생성
- 준비
	- 디스패치: 새로운 프로세스를 실행상태로 변경
- 실행
	- 타임 아웃: 주어진 타임 슬라이스를 모두 사용하여 준비상태로 변경 (인터럽트를 이용하여 알림)
- 대기 상태: 입출력 요청이 완료될 때까지 기다리는 상태
	- 입출력 장치에서 작업이 완료되면 인터럽트를 요청하여 준비 상태로 이동
- 완료
	- PCB를 삭제
	- 코어덤프: 종료 직전 메모리 상태를 저장장치에 저장

### 휴식 상태
- 프로세스가 완전히 종료하지 않고 잠시 멈출 필요가 있을 경우 사용하는 상태
	- ctrl + z를 이용하여 중단시킬 수 있다
- 메모리영역과 PCB를 유지하면서 resume 명령어를 사용하면 즉시 준비 실행상태로 돌아간다.
### 일곱 가지 상태 (대기 보류, 준비 보류)
- 보류 상태가 추가됨
- 보류 상태: 프로세스가 메모리 밖으로 쫓겨난 상태
	- 메모리 공간을 확보하기 위한 스왑대상이 된 경우
	- 프로그램의 오류나 바이러스가 의심되는 경우 다른 프로세스를 보호하기 위해서
	- 입출력이 긴 시간 지연되는 경우

# 프로세스 제어 블록과 문맥 교환
## 프로세스 제어 블록
- 프로세스 제어 블록 (PCB: Process Control Block)
	- 프로세스를 실행하는 데 필요한 중요한 정보를 보관하는 자료구조
	- 프로세스가 생성될 때 만들어져 프로세스 실행이 완료되면 폐기
### 데이터
- 포인터: 큐를 구현할때 사용
- 프로세스 상태: 프로세스의 현재 상태
- 프로세스 구분자: 프로세스를 구분하기 위한 구분자
- 프로그램 카운터: 다음 실행될 명령어의 위치
- 프로세스 우선순위: 스케줄링에 사용하는 우선순위가 저장
- 각종 CPU 레지스터 정보: 프로세스가 중단 될 때 CPU가 사용하던 레지스터 값을 저장
- 메모리 관리 정보: 프로세스가 할당 받은 메모리 영역의 주소
	- 경계, 한계 레지스터, 세그먼트와 페이지 테이블 정보
- 할당된 자원 정보: 프로세스 실행을 위한 입출력 자원이나 오픈 파일 정보를 저장
- 계정 정보: 프로세스를 생성한 계정의 정보와 CPU할당 시간과 사용 시간 등의 정보
- 부모 프로세스 구분자와 자식 프로세스 구분자: 자식 프로세스와 부모 프로세스의 PID를 저장
## 문맥 교환
- CPU를 사용하던 프로세스가 나가고 새로운 프로세스에게 CPU를 할당하는 작업

### 문맥 교환 절차
- 실행 상태의 프로세스가 타임 슬라이스를 전부 사용하여 타임 아웃 발생
- 기존의 프로세스의 상태를 PCB에 저장
- 새로운 프로세스의 상태를 PCB에서 가져와 CPU에 세팅
- 새로운 프로세스를 실행 상태로 이동하여 작업 실행

#### 문맥 교환이 일어나는 경우
- 타임 아웃이 발생한 경우
- 인터럽트가 발생한 경우
### 문맥 교환과 타임 슬라이스의 크기
- 타임 슬라이스가 너무 큰 경우
	- 한 프로세스가 오래 작업하여 다른 프로세스가 끊어져보임
	- 문맥 교환이 적게 발생함
- 타임 슬라이스가 너무 작은 경우
	- 문맥 교환이 자주 발생함
	- 여러 프로세스가 동시에 실행되는 것처럼 보임
# 프로세스의 연산
## 프로세스 구조
- 코드 영역
	- 프로그램의 본문이 기술된 곳
	- 프로그래머가 작성한 프로그램이 읽기 전용으로 처리됨
- 데이터 영역
	- 코드가 실행되면서 사용하는 변수나 파일등 데이터를 모아놓는 곳
	- 읽기 쓰기 모두 가능
	- static이나 전역변수만 저장
	- .bss: 초기값이 없거나 0인 데이터
		- 공간만 할당하고 데이터를 저장하지 않음
	- .data: 초기값이 있는 데이터
		- 실제로 값을 기록함
- 스택 영역:
	- 프로세스를 실행하면서 부수적으로 필요한 데이터를 저장하는 공간
## 프로세스의 생성과 복사
- 프로세스를 생성하는 방법은 새 프로세스를 생성하거나 실행중인 프로세스에서 복사하는 방법이 있다.
### fork() 시스템 호출의 개념
- 실행 중인 프로세스로부터 새로운 프로세스를 복사하는 커널 함수
	- 실행중인 프로세스와 똑같은 프로세스가 하나 더 만들어진다
- 기존 프로세스가 부모 프로세스가 되고 새로 생긴 프로세스가 자식 프로세스로 연결된다.

### fork() 시스템 호출의 동작 과정
- PCB를 포함한 프로세스 영역의 대부분이 자식 프로세스로 복사되어 똑같은 프로세스가 만들어 진다.
	- 변경되는 내용
		- PID
		- 메모리 관련 정보
		- 부모 프로세스와 자식 프로세스 정보
### 장점
- 프로세스 생성 속도가 빠르다
	- 보조 기억 장치가 아닌 기존의 메모리에 있는 데이터를 복사하기 때문에 빠르다
- 추가 작업 없이 자원을 상속 할 수 있다
	- 부모 프로세스가 사용하는 모든 자원을 자식 프로세스가 사용 가능하다
- 시스템 관리를 효율적으로 할 수 있다.
	- 두 프로세스가 부모 자식 관계로 연결되어 있기 때문에 자식 프로세스를 종료하면 부모 프로세스가 자원을 정리 할 수 있음
## 프로세스의 전환
### exec() 시스템 호출의 개념
- 기존 프로세스를 새로운 프로세스로 전환하는 함수
	- 프로세스의 구조를 재활용하기 위해서 사용
		- 이미 만들어진 PCB, 메모리 영역, 부모 자식 관계를 그대로 사용할 수 있음

### exec() 시스템 호출의 동작 과정
- 코드 영역과 데이터 영역에 있는 내용이 모두 지워지고 새로운 코드와 데이터로 변경함
- PCB의 레지스터 값과 파일 관련된 정보등이 변경됨
	- 프로세스 구분자, 부모자식 정보, 메모리 관련 정보는 변경되지 않음

	- 자식 프로세스가 종료되었는데 부모 프로세스가 자식 프로세스의 자원을 회수하지 않는 경우
# 스레드
## 스레드의 개념
- 프로세스의 코드에 정의된 절차에 따라 CPU에 작업 요청을 하는 실행 단위
- 프로세스가 CPU에게 전달하는 하나의 작업 단위
- 운영체제 입장에서는 프로세스가 작업 단위이고 CPU입장에서는 스레드가 하나의 작업 단위이다.

### 프로세스와 스레드의 차이
- 프로세스끼리는 약하게 연결됨
- 스레드끼리는 강하게 연결됨

#### 멀티태스크
- 서로 독립적인 
#### 멀티 스레드

- 초기에는 CPU의 작업 단위는 프로세스 하나뿐이 였다
	- 멀티 코어 CPU가 생겨나면서 멀티 스레드를 지원함
	- 프로세스를 여러 스레드로 나누어 여러 개의 코어에 배분함으로써 시스템의 효율을 높임

### 스레드 관련 용어
#### 멀티스레드
- 프로세스 내 작업을 여러 개의 스레드로 분할하여 작업의 부담을 줄이는 프로세스 운영 기법
#### 멀티태스킹
- 시분할 시스템: CPU에게 작업을 전달할 때 시간을 잘게 나누어 전달
- 이때 CPU에게 전달하는 작업은 스레드 이다.
#### 멀티프로세스
- CPU 여러 개를 사용하여 여러 개의 스레드를 동시에 처리하는 작업 환경
- 하나의 CPU의 여러 개의 코어에 스레드를 배정하여 동시에 작동하는 것
- 여러 개의 CPU에 여러 개의 스레드를 배정하는 동시에 작동하는 것
#### CPU 멀티스레드
- 스레드를 잘게 쪼개어 동시에 처리하는 명령어를 병렬로 처리하는 기법
- 인텔의 하이퍼스레딩
## 멀티스레드의 구조와 예
- 스레드는 멀티 태스킹의 낭비 요소를 제거하기 위해서 사용
	- 기존에는 fork로 자식 프로세스를 생성하는 방식으로 동작함
		- 기존에는 CPU의 작업 단위는 프로세스임 -> 다른 일을 병렬로 처리하기 위해서 자식 프로세스를 만들어서 작업하도록함

### fork를 이용한 멀티 태스킹시 낭비 요소
- 코드 영역과 데이터 영역의 일부 메모리가 중복됨
- 생성을 위한 시스템 호출 비용
- 문맥 교환 비용
- 프로세스간 데이터 공유 비용
### 멀티스레드의 구조
- 하나의 프로세스내에서 여러 개의 스레드를 생성함
	- 정적 영역: 프로세스가 실행되는 동안 변경되지 않는 영역
		- 코드
		- 전역 데이터
		- 파일
		- 정적 영역은 스레드 끼리 공유하여 사용
	- 동적영역: 작업을 하면서 값이 바뀌거나 새로 만들어지는 영역
		- 레지스터 값
		- 스택
		- 힙
		- 동적 영역은 스레드마다 구분되어 사용
- 정적 영역간 자원을 공유 하여 사용하여 자원의 낭비를 줄임

- 스레드는 LWP(Light Weight Process)로 부름
	- 스레드가 1개인 프로세스는 HWP(Heavy Weight Process)라고 부름

## 멀티스레드의 장단점
### 멀티스레드의 장점
- 응답성 향상: 한 스레드가 입출력으로 멈춰 있어도 다른 스레드는 작업 가능하다
- 자원 공유: 프로세스가 가진 자원을 스레드간 공유하여 사용할 수 있음
- 효율성 향상: 불필요한 자원의 중복을 막음
- 다중 CPU 지원: 다중 CPU가 멀티스레드를 동시에 처리하여 CPU사용량이 증가하고 프로세스 처리 시간을 단축할 수 있다.

### 멀티스레드의 단점
- 스레드간 자원을 공유하기 때문에 한 스레드에 문제가 발생하면 전체 프로세스에 문제가 발생함
## 멀티스레드 모델
- 스레드도 커널과 사용자로 나눔
- 커널 스레드는 커널이 생성하고 관리함
- 커널 스레드와 사용자 스레드의 대응 방식에 따라 분류함
### 사용자 스레드 (1 to N 모델)
- 커널이 멀티스레드를 지원하지 않던 초기에 사용된 방식
- 사용자 레벨에서 라이브러리를 사용하여 구현함
	- 라이브러리가 커널이 지원하는 스케줄링, 동기화 등의 기능을 대신 구현함
- 여러 개의 사용자 스레드가 하나의 커널 스레드에 연결됨
	- 커널 입장에서는 사용자 스레드가 하나의 프로세스로 보임

- 장점
	- 라이브러리가 직접 스케줄링하고 정보를 처리하므로 문맥 교환이 필요 없음
- 단점
	- 여러 개의 스레드가 하나의 커널 스레드와 연결되므로 하나가 입출력으로 대기 상태에 들어가면 모든 사용자 스레드가 같이 대기함
	- 한 프로세스의 타임 슬라이스를 여러 스레드가 공유하므로 여러 CPU를 동시에 사용할 수 없음
	- 공유 변수를 보호하는 장치를 라이브러리 레벨에서 구현해야 하므로 보안에 취약함
### 커널 스레드 (1 to 1 모델)
- 하나의 사용자 스레드에 하나의 커널 스레드가 연결됨
- 커널이 멀티스레드를 지원하는 방식
- 스레드가 독립적으로 스케줄링되므로 특정 스레드가 대기 상태에 들어가도 다른 스레드는 작업을 계속함
- 커널이 제공하는 보호 기능 등을 사용할 수 있음

- 장점
	- 커널 레벨에서 작업을 지원하므로 멀티 CPU 사용이 가능함
	- 하나의 스레드가 대기 상태에 있어도 다른 스레드는 작업을 계속할 수 있음
	- 커널의 기능을 사용하므로 보안에 강하고 안정적임
- 단점
	- 문맥 교환 시 오버헤드로 인해 느리게 작동함
### 멀티 레벨 스레드 (N to M 모델)
- 사용자 스레드와 커널 스레드를 혼합한 방식
	- 커널 스레드의 개수가 사용자 스레드보다 같거나 작음
- 사용자 스레드와 커널 스레드의 장단점을 모두 가짐
	- 하나의 커널 스레드가 대기 상태에 들어가면 다른 커널 스레드가 대신 작업하여 유연한 처리가 가능함
	- 문맥 교환 시 오버헤드가 존재하여 사용자 스레드만큼 빠르지 않음
- 빠르게 움직여야 하는 스레드는 사용자 스레드로, 안정적으로 움직여야 하는 스레드는 커널 스레드로 작동함
# 동적 할당 영역과 시스템 호출
## 프로세스의 동적 할당 영역
- 정적 할당 영역: 코드 영역, 데이터 영역
	- 프로세스가 실행되기 직전에 위치와 크기가 결정되고 변하지 않음
- 동적 할당 영역: 스택 영역, 힙 영역
	- 프로세스가 실행되는 동안 만들어지는 영역으로 크기가 늘기도 줄기도 함
### 스택
- 함수 호출 시 되돌아올 메모리 주소를 저장함
	- 호출한 함수가 종료되면 저장된 주소로 되돌아가 호출 전 코드를 이어서 실행함
- 변수의 사용 범위(스코프)를 구현할 때 사용함
	- 전역 변수: 프로그램 내 모든 함수에서 사용 가능
	- 지역 변수: 특정 함수 내에서만 사용 가능
		- 함수가 종료되면 공간을 반환해야 하므로 스택에 저장함
- 스레드가 작동하는 동안 추가되거나 삭제되는 동적 할당 영역임
- 모든 코드를 하나로 묶으면 스택 유지 비용이 줄어 성능은 좋아짐
	- 오류를 찾기 어렵고 재사용이 어려우며 여러 사람이 나누어 작업하기 어려움
### 힙
- 동적으로 할당되는 변수 영역
	- 프로그램이 실행되는 동안 런타임에 할당됨
- 동적으로 할당된 메모리는 반드시 반환하여 메모리 낭비를 막아야 함
- 포인터와 동적 할당을 이용하면 필요할 때 메모리를 사용하고 필요 없을 때 반환하여 메모리를 효율적으로 관리 가능함

## exit()과 wait() 시스템 호출
### exit() 시스템 호출
- 작업의 종료를 알려주는 시스템 호출
- 부모 프로세스가 자식 프로세스가 사용하던 자원을 빠르게 정리할 수 있음
### wait() 시스템 호출
- 자식 프로세스가 종료되는 것을 기다렸다가 종료되면 다음 문장을 실행함
	- 부모 프로세스가 먼저 종료되어 고아 프로세스가 생기는 것을 방지함
- 부모 프로세스와 자식 프로세스 간 동기화에도 사용됨
- 전면 프로세스와 후면 프로세스를 구현할 때 사용됨
	- 전면 프로세스: 셸이 wait()을 사용하므로 작업이 끝날 때까지 다음 명령어의 입력을 받지 않음
	- 후면 프로세스: 셸이 wait()을 사용하지 않으므로 다음 명령어를 바로 받을 수 있음
