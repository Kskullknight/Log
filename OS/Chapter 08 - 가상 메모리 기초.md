# 가상 메모리의 개요
## 가상 메모리 시스템
### 가상 메모리 개념
- 모든 프로세스는 메모리의 어느 위치에 있는지 상관없이 0번부터 시작하는 연속된 메모리 공간을 사용할 수 있도록 하는 기술
	- 물리 메모리의 크기와 프로세스가 올라갈 메모리의 위치를 신경쓰지 않고 프로그래밍하도록 지원함

### 가상 메모리의 크기와 주소
- 물리 메모리 공간이 아닌 가상 주소 공간을 가짐
	- 프로세스 -> 메모리 관리 -> (물리 메모리, 스왑 영역)
	- 이론적으로 가상 메모리의 크기는 무한함
		- 하지만 실제로는 컴퓨터 시스템이 가질 수 있는 물리 메모리의 최대 크기로 한정됨
			- 32bit: 4G
#### 스왑
- 보조저장 장치의 일부 공간에 메모리처럼 사용하도록 함
	- 메모리 관리자가 관리하는 영역으로 메모리의 일부
- **스왑 아웃**: 물리 메모리에 저장된 프로세스 일부를 보조 메모리의 스왑 영역에 저장함
- **스왑 인**: 스왑 영역에 있는 정보를 물리 메모리에 저장함

#### 메모리 관리자
- 프로세스가 제약 없이 사용자 데이터를 물리 메모리에 배치 할 수 있도록 함
- 물리 메모리를 나누는 방법, 프로세스 배치 위치, 물리 메모리 부족 시 대처 등을 담당함
- 동적 주소 변환 (DAT: Dynamic Address Translation)
	- 물리 메모리와 스왑영역을 합쳐 프로세스가 사용하는 가상 메모리를 실제 메모리의 물리 주소로 변환한다.

## 매핑 테이블의 필요성과 역할
- 메모리는 매핑 테이블을 작성하여 관리함
- 메모리 관리자는 가상 주소와 물리 주소를 일대일로 매핑한 테이블로 관리함
	- 메모리 분할 방식
		- 가변 분할 방식(세그먼테이션 기법)
			- 세그먼테이션 매핑 테이블
		- 고정 분할 방식 (페이징 기법)
			- 페이지 매핑 테이블

## 지역성
- 개념
	- 기억 장치에 접근하는 패턴이 메모리 전체에 고루 분포되는 것이 아니라 특정 영역에 집중되는 성질
- 종류
	- **공간의 지역성**
		- 현재 위치에서 가까운 데이터에 접근할 확률이 먼 거리에 있는 데이터 접근할 확률보다 높음
	- 시간의 지역성
		- 현재를 기준으로 가장 가까운 시간에 접근한 데이터가 더 먼 시간에 접근한 데이터보다 사용될 확률이 높음
	- 순차적 지역성
		- 작업이 순서대로 진행되는 것
- 캐시는 지역성 이론을 사용하는 대표적인 장치임

# 페이지 기법
- 물리 주소 공간을 같은 크기로 나누는 고정 분할 방식을 이용한 가상 메모리 관리 기법
- 가상 주소는 프로세스 입장에서 바라본 메모리 공간은 항상 0번부터 시작하도록 한다.

## 페이징 기법의 구현
### 구성
- **페이지**
	- 가상 주소의 분할된 각 영역
- **프레임**
	- 물리 주소의 분할된 각 영역
- 페이지와 프레임의 크기는 같다
	- 따라서 페이지는 어떤 프레임에도 배치할 수 있다

- **페이지 테이블**
	- 어떤 페이지가 어떤 프레임에 있는지에 대한 연결 정보가 담겨 있다
	- 하나의 열로 구성되어 모든 페이지 정보를 순서대로 가지고 있다
		- 위에서부터 차례대로 페이지 0, 페이지 1, ....
	- 연결된 프레임 번호를 순서대로 가짐
		- 첫 번째 열 - 페이지 0에 해당하는 프레임 번호
		- 없는 경우 `invalid`값을 가진다

## 페이지 기법의 주소 변환 과정
- 가상 주소 n번이 어느 페이지에 있는지 찾는다. n -> $P_k$ 의 0번에 위치
- 페이지 테이블의 페이지 k로 가서 프레임 m에 있다는 것을 확인한다.
	- 페이지 테이블의 k번째를 확인
- 물리 메모리 프레임의 m의 0번 위치에 접근한다
	- 가상 주소 n의 위치는 m의 0번이다

### 정형화된 주소 변환
#### 변수
- 가상 주소: VA
- 물리 주소: PA
- 페이지: P
- 프레임: F
- 오프셋: D

### 변환 과정
- VA = `<P, D>` -> PA = `<F, D>`
- 페이지 테이블의 각 한 줄을 **페이지 테이블 엔트리**(PTE: Page Table Entry)라고 한다
	- PTE n은 페이지 n에 해당하는 프레임 m을 저장한다.

### 16bit CPU의 주소 변환 예
### 상황
- CPU가 사용가능한 메모리 크기는 64KB
- 프로세스가 사용 가능한 가상 주소 공간은 64KB
- 실제 메모리의 크기 32KB
- 한 페이지의 크기는 1KB
#### 동작
- 한 페이지의 크기가 1KB이므로 페이지의 개수는 64개가 됨
- 가상 주소에서 처음은 페이지 번호 나머지는 페이지 내에서 몇번째에 위치하는지에 대한 거리를 나타냄
	- `<P, D>`
	- 페이지의 개수가 64개이므로 P는 6bit를 차지하고 나머지 10bit에 거리를 저장함
- 페이지 테이블의 크기는 가상 주소 공간의 개수에 따라 구성되기 때문에 64개의 PTE를 가진다.
- 페이지의 크기가 1KB이고 물리 주소의 크기가 32KB이므로 32개의 프레임을 가진다
	- 페이지의 개수에 비해 프레임의 개수가 부족한 부분은 스왑영역에 저장한다.

#### 예시
1. 가상 주소 980번의 페이지는 P = (980 / 1024) = 0, D = (980 % 1024) = 980이므로 VA = `<0, 980>`
	- 0 페이지의 980번째에 위치함
2. 페이지 테이블에서 PTE 0에서 페이지가 가리키는 프레임을 확인
	- 프레임 2에 저장됨을 확인
3. 물리 메모리의 프레임 2 시작지점으로부터 980번 떨어진 곳에 접근하여 데이터를 가져옴

## 페이지 테이블 관리
### 메모리 공유 
- 페이지 테이블은 모든 프로세스마다 하나씩 가짐
- 페이지 테이블은 메모리 관리자가 자주 사용하는 자료구조이므로 운영체제 영역의 일부분에 모아놓는다
- 페이지 테이블이 차지하는 영역은 프로세스의 개수에 비례하여 커진다
- 프로세스가 많은 경우 프로세스가 사용할 메모리 영역이 줄어드는 문제가 발생한다.
- 물리 메모리의 크기가 작을 때는 페이지 테이블도 스왑영역으로 이동된다.
- 페이지 테이블에 접근하기 위해서 별도의 **페이지 테이블 기준 레지스터**(PTBR: Page Table Base Register)에 저장한다
	- PTBR은 페이지 테이블의 시작 주소를 가진다.

### 쓰기 시점 복사
- fork()와 같이 동일한 프로그램을 다른 프로세스로 실행하는 경우 메인 코드의 경우 두 프로세스가 공유 가능하기 때문에 공유하여 사용하면 메모리의 용량을 아낄 수 있다.
	- 하지만 두 프로세스에서 서로 다르게 사용하는 데이터의 경우 다른 메모리 영역에 저장해야함
- 그래서 새로운 데이터를 쓰기 시작한 시점에 새로운 메모리 영역을 확보하고 사용한다
	- 이를 쓰기 시점 복사(Copy on Write)라고 한다.

### 변환 색인 버퍼(TLB: Translation Look-aside Buffer)
- MMU가 가상 주소를 통해 물리주소로 접근하기 위해서는 두 번의 메모리 접근이 필요함
	1. 페이지 테이블 접근 - 물리 주소 확인
	2. 물리 주소 접근 - 물리 주소를 통해 접근
	- 이러한 방식은 CPU의 성능을 떨어뜨림
- 페이지 테이블의 일부 정보를 CPU 안쪽으로 가져옴 — TLB
	- 지역성 이론에 근거하여 사용이 예상되는 페이지 테이블 일부를 CPU 안쪽으로 가져온다.
- 전체 페이지의 일부만 있으므로 2개의 열이 존재함
	- 페이지 - 프레임
#### 동작 과정
- 캐시 시스템과 유사하게 동작함

1. 주소 변환을 위해 색인 버퍼를 확인한다
	1. 원하는 페이지가 있는 경우 — TLB hit => 즉시 물리 주소 반환
	2. 원하는 페이지가 없는 경우 — TLB miss => 메모리에 있는 페이지 테이블에 접근하여 프레임 주소를 확인함
2. TLB에서 원하는 페이지를 확인하는 방법은 하드웨어적으로 병렬로 검색이 가능하다.
	- 한번에 모든 행에서 원하는 페이지를 확인할 수 있음

### 역페이지 테이블(inverted page table)
- 기존의 페이지 테이블과 반대로 프레임을 기준으로 페이지의 번호를 한 개의 열에 저장함
- 프로세스의 수와 상관없이 오직 하나만 존재함
	- 페이지 테이블이 차지하는 영역이 매우 작아짐
- 하나의 행에 PID와 페이지 번호를 저장함
	- 해당 프레임을 사용하는 PID와 페이지의 번호를 저장
- 물리 메모리에 접근하기 위해서는 최악의 경우 테이블의 모든 행을 확인해야 함

### 다단계 페이지 테이블(Multi-page mapping)
- 일정 크기로 자른 페이지 테이블을 바깥쪽에서 관리하는 새로운 테이블을 추가한 방식
	- VA = `<P1, P2, D>`
- 페이지의 주소를 더 상세하게 나누어서 관리함
	- 페이지 테이블의 크기가 큰 경우 3단계나 4단계로 단계를 늘려서 관리할 수도 있다.
- 페이지 테이블 전체를 만들지 않고 필요한 땐 추가할 수 있기 때문에 메모리를 효율적으로 관리할 수 있음

# 세그먼테이션 기법
- 물리 메모리를 프로세스 크기에 따라 가변적으로 나누어 사용하는 가상 메모리 관리 기법
- 물리 메모리에서 프로세스가 필요한 만큼 할당받아서 사용하는 방식

## 세그먼테이션 기법의 구현
- 페이지 기법과 유사하게 세그먼테이션 테이블을 사용
	- 세그먼트의 번호를 기준으로 세그먼트의 크기와 물리 메모리 시작 주소를 가짐
- 프로세스마다 세그먼테이션 테이블을 가짐

## 세그먼테이션 기법의 주소 변환
- VA = `<S, D>`로 표현함
	- S: 세그먼트의 번호
	- D: 거리

- 세그먼테이션 테이블에서 세그먼트 번호에 저장된 limit과 address 값을 확인한다
- limit + address를 통해 확인하려는 주소가 세그먼트 영역을 벗어나는지 확인한다.
	- 벗어나는 경우 segment fault 발생
	- 포함되는 경우 address + distance가 물리 주소가 된다.

# 캐시 매핑 기법
## 캐시 직접 매핑
- 메모리를 일정 크기로 나누어 각 덩어리를 페이지 P라고 한다.
	- P는 페이지 번호, D는 페이지 내에서 거리를 의미한다
