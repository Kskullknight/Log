# 네트워크와 인터넷
## 통신과 네트워크
### 통신 환경의 발전
- 통신(communication): 서로 의사소통하는 것
	- 통신 기술은 단방향 => 양방향, 일대일 => 일대다로 발전해 옴

#### 모스 부호
- 전기를 이용한 최초의 통신 수단
- 미리 정해놓은 짧은 음과 긴 음을 조합하여 먼 곳에 있는 사람에게 실시간으로 문자를 전송
- 단방향 통신

#### 전화
- 통신하려는 대상을 선으로 연결하여 사람의 음성을 전달
- 양방향 통신

#### 무전기
- 최초의 무선 통신 기기
- 한쪽이 말하는 동안 다른 쪽은 들을 수만 있음
	- 반양방향 통신(half duplex)

#### 라디오와 TV
- 무선 통신 기술이 발달하면서 등장한 시스템
- 라디오: 많은 사람이 뉴스나 음악을 쉽게 접할 수 있게 해준 무선 통신 기기
	- 말하는 사람을 직접 볼 수 없음
- TV: 말하는 사람의 얼굴을 직접 볼 수 있게 됨
- 송신 측에서 많은 사람에게 무작위로 전파하는 단방향 통신
- **방송(broadcast)**: 단방향으로 일대다 통신을 하는 것

#### IPTV
- 인터넷을 이용하여 방송
- 사용자가 원하는 영화나 프로그램을 골라서 볼 수 있음
- 양방향 통신 서비스

| 통신 수단   | 유/무선 | 방향    | 대상  |
| ------- | ---- | ----- | --- |
| 모스 부호   | 유선   | 단방향   | 일대일 |
| 전화      | 유선   | 양방향   | 일대일 |
| 무전기     | 무선   | 반양방향  | 일대일 |
| 라디오, TV | 무선   | 단방향   | 일대다 |
| IPTV    | 유선   | 양방향   | 일대다 |

> [!note]+ 통신 방향에 따른 분류
>
> - 단방향(simplex): 한쪽에서만 보내고 다른 쪽은 받기만 함
>     - 라디오, TV
> - 반양방향(half duplex): 양쪽이 보낼 수 있지만 동시에 보낼 수는 없음
>     - 무전기
> - 양방향(full duplex): 양쪽이 동시에 보내고 받을 수 있음
>     - 전화

### 네트워크 환경의 발전
- 네트워크: 유/무선 통신 기술을 이용하여 여러 기기를 하나로 연결한 것
- 전송 신호에 따라 아날로그망과 디지털망으로 나뉨
	- 아날로그망: 음성 신호를 전송
	- 디지털망: 디지털 데이터를 전송

#### 전화망
- 일상 생활에서 가장 많이 사용되는 네트워크
- 각각의 전화기가 교환기로 묶여 있고, 한쪽에서 전화번호를 누르면 교환기가 해당 전화로 연결
- PSTN(Public Switched Telephone Network): 초기의 유선으로 구축되어 음성을 전송하는 전화망
	- 공중 전화 교환망

#### 무선 전화망의 세대별 발전

| 세대      | 특징                                                |
| ------- | ------------------------------------------------- |
| 1세대(1G) | 아날로그 신호만 전송                                       |
| 2세대(2G) | 같은 통신망에 디지털 신호를 전송                                 |
| 3세대(3G) | 휴대전화로도 인터넷을 사용할 수 있게 지원, 기존 전화 기능에 데이터 통신 기능을 추가      |
| 4세대(4G) | 데이터 전송 속도를 높임, 스마트폰이 보급되어 데이터 사용량이 급격히 늘고 음성 통화는 줄어듦 |
| 5세대(5G) | 초고속 무선 통신이 가능                                     |

> [!note]+ 세대별 대표 기술
>
> - 2G: GSM, CDMA
> - 3G: WCDMA, HSDPA
> - 4G: LTE, LTE-A
> - 5G: NR(New Radio)

### 네트워크 구성 방식
- 여러 컴퓨터를 연결하여 하나의 시스템처럼 사용하는 방식은 메모리를 공유하는지에 따라 구분됨

#### 강결합 시스템
- 네트워크로 연결된 모든 컴퓨터의 프로세서가 하나의 메모리를 공유하는 방식
- 모든 컴퓨터가 메모리를 공유하면서 같은 운영체제를 사용
- 장점
	- 메모리를 통해 데이터를 주고받기 때문에 속도가 빠름
- 단점
	- 여러 프로세서가 공유 메모리를 서로 사용하려고 경쟁함
		- **결합 교환**으로 해결
- 결합 교환: 하나의 공유 메모리를 차지하려는 여러 프로세서 중 하나만 골라서 메모리 접근을 허락하는 방식

#### 약결합 시스템
- 둘 이상의 독립된 시스템을 연결한 것
	- 오늘날의 네트워크 방식
- 각 시스템은 자신만의 운영체제, 메모리, 프로세서, 입출력장치를 가지고 독립적으로 운영됨
	- 필요할 때 통신선을 이용하여 **메시지 전달**이나 **원격 프로시저 호출(RPC)** 로 통신
- 장점
	- 하나의 시스템에 장애가 발생해도 다른 시스템에 영향을 끼치지 않음
- 단점
	- 통신 오버헤드가 있기 때문에 느림

| 구분    | 강결합 시스템            | 약결합 시스템                  |
| ----- | ------------------ | ------------------------ |
| 메모리   | 하나의 메모리를 공유        | 각 시스템이 독립된 메모리를 가짐        |
| 운영체제  | 같은 운영체제를 사용        | 각 시스템이 자신만의 운영체제를 가짐      |
| 통신 방법 | 공유 메모리             | 메시지 전달, 원격 프로시저 호출        |
| 속도    | 빠름                 | 통신 오버헤드로 느림              |
| 장애    | 공유 메모리에 문제 발생 시 전체 영향 | 한 시스템의 장애가 다른 시스템에 영향 없음 |
| 예     | 멀티프로세서 컴퓨터         | 오늘날의 네트워크, 분산 시스템        |

> [!note]+ 원격 프로시저 호출(RPC: Remote Procedure Call)
>
> - 네트워크 너머에 있는 다른 컴퓨터의 함수(프로시저)를 마치 자기 컴퓨터의 함수처럼 호출하는 방식
>     - 호출하는 쪽은 내부적으로 메시지가 오가는 것을 신경 쓰지 않아도 됨
> - 메시지 전달을 추상화한 통신 방법으로, 오늘날 gRPC 등으로 이어짐

### 프로토콜
- 컴퓨터와 컴퓨터를 전선으로 연결하여 데이터를 전송하는 방법이 개발됨
- 프로토콜(protocol): 다른 기기 간에 통신을 하기 위해 정한 약속
	- 데이터의 형식, 전송 순서, 오류 처리 방법 등을 정의
- 네트워크를 구성하기 위해 필요한 것
	- 하드웨어: 두 기기를 물리적으로 연결
	- 소프트웨어: 프로토콜을 마련
- 네트워크를 배운다는 것은 하드웨어의 특성과 프로토콜이 어떤 일을 하는지 배우는 것

## 인터넷
### LAN 기술의 이해
- LAN(Local Area Network): 가까운 거리에 연결된 네트워크
	- 몇 킬로미터 이내의 네트워크를 연결
	- 건물, 학교, 회사 단위
- WAN(Wide Area Network): 국가 전체 또는 국가 간에 연결되어 있는 네트워크

#### 토폴로지
- 컴퓨터 여러 대를 연결하는 LAN의 구조(연결 형태)

| 토폴로지 | 구조                               | 프로토콜         |
| ---- | -------------------------------- | ------------ |
| 스타형  | 중간에 네트워크를 관장하는 시스템을 두고 방사형으로 기기를 연결 | -            |
| 링형   | 모든 기기를 원형으로 연결                   | 토큰링 방식(FDDI) |
| 버스형  | 중앙의 버스에 독립적으로 기기를 붙여 네트워크를 구성       | CSMA/CD      |

- 스타형(star)
	- 중앙 장치(허브, 스위치)에 모든 기기가 연결됨
	- 중앙 장치에 장애가 발생하면 전체 네트워크가 마비됨
	- 오늘날 가장 많이 사용되는 구조
- 링형(ring)
	- 모든 기기를 원형으로 연결
	- 토큰(token)을 가진 기기만 데이터를 전송할 수 있음
		- 토큰링 방식(FDDI: Fiber Distributed Data Interface)
	- 충돌이 발생하지 않음
- 버스형(bus)
	- 중앙의 하나의 버스(케이블)에 모든 기기를 붙여서 구성
	- 하나의 선을 공유하기 때문에 충돌이 발생할 수 있음
		- CSMA/CD 프로토콜로 해결

> [!note]+ CSMA/CD(Carrier Sense Multiple Access with Collision Detection)
>
> - 버스형 LAN(초기 이더넷)에서 사용하는 매체 접근 프로토콜
>     - Carrier Sense: 전송하기 전에 선이 비어 있는지 먼저 확인
>     - Multiple Access: 여러 기기가 하나의 선을 공유
>     - Collision Detection: 전송 중 충돌이 감지되면 전송을 멈추고 임의의 시간을 기다린 후 재전송
> - 10장의 버스 구조에서 여러 장치가 하나의 채널을 공유할 때 발생하는 문제와 같은 맥락

### 인터넷의 등장과 발전
#### ARPA넷
- 미국 국방성(ARPA)에서 서로 호환되지 않는 LAN을 묶어 하나의 네트워크로 만듦
	- 여러 종류의 LAN을 선으로 연결하여 하나의 네트워크로 만듦
- 인터넷(Internet)의 시작
	- Inter + Network: 네트워크와 네트워크를 연결한 네트워크

#### IP와 TCP
- IP(Internet Protocol)
	- 서로 다른 LAN 사이에서 목적지까지 데이터를 보내는 프로토콜
	- 목적지까지 데이터를 보내는 일은 훌륭히 수행함
	- 데이터가 제대로 전달되지 않거나 중간에 없어지는 문제가 발생함
- TCP(Transmission Control Protocol)
	- IP의 문제를 보완하기 위해 만든 데이터 전송 시 오류를 바로잡는 프로토콜
	- IP 위에서 동작하도록 설계됨
- TCP/IP
	- TCP와 IP를 묶어서 부르는 이름
	- 오늘날 인터넷의 표준 프로토콜

| 프로토콜 | 역할                | 특징                        |
| ---- | ----------------- | ------------------------- |
| IP   | 목적지까지 데이터(패킷)를 전달 | 전달을 보장하지 않음(비신뢰성), 순서가 바뀌거나 유실될 수 있음 |
| TCP  | 데이터 전송 오류를 바로잡음   | IP 위에서 동작, 순서 보장과 재전송으로 신뢰성 확보 |

> [!note]+ IP는 왜 데이터를 잃어버리나?
>
> - IP는 데이터를 패킷(packet) 단위로 나누어 보내고, 각 패킷은 서로 다른 경로로 전달될 수 있음
>     - 중간 장비(라우터)가 혼잡하면 패킷을 버림
>     - 경로가 다르면 도착 순서가 뒤바뀜
> - TCP는 패킷에 순서 번호를 붙이고, 받은 쪽이 잘 받았다는 응답(ACK)을 보내지 않으면 다시 보내는 방식으로 이를 해결함
