# 오픈 소스에서 사용하는 커버리지
- 오픈 소스 프로젝트 커버리지의 특징
	- 측정 기준은 대부분 구문(라인) 커버리지 + 분기 커버리지 수준까지만 사용 
		- (MC/DC 같은 고비용 기준은 거의 사용하지 않음)
	- 전체 커버리지 수치보다 PR에서 바뀐 줄이 테스트(패치 커버리지, diff coverage)

## 실제 오픈 소스 프로젝트 사례 

| 프로젝트                | 언어       | 도구                     | 머지 기준 (미달 시 차단)                                                      | 현재 수치                | 숫자 종류    |
| ------------------- | -------- | ---------------------- | -------------------------------------------------------------------- | -------------------- | -------- |
| pytest              | Python   | coverage.py + Codecov  | patch 100%                                                           | -                    | 목표치      |
| Apache Commons Lang | Java     | JaCoCo (Maven)         | class 98% / instruction 96% / method 96% / line 96% / branch 92% / complexity 91% | -                    | 래칫(하한선)  |
| Node.js (core)      | JS + C++ | c8, gcov/lcov + Codecov | 없음 (측정·공개만)                                                          | JS 94.3% / C++ 91.4% | 측정값      |
| Django              | Python   | coverage.py + diff-cover | 없음 (PR 변경 줄 경고만)                                                    | -                    | -        |
| Kubernetes          | Go       | go test + gopherage    | 없음 (1시간 주기 측정만)                                                      | -                    | -        |
| Linux 커널            | C        | gcov, KCOV             | 없음                                                                   | -                    | -        |
| CPython             | C/Python | coverage.py            | 없음                                                                   | -                    | -        |

# 회사에서 주로 사용하는 커버리지
- 회사(기업) 커버리지의 특징
	- 목적이 "공개 신뢰"가 아니라 배포 게이트·품질 게이트·감사(audit) 증빙
	- 커버리지 도구를 단독으로 쓰기보다 정적 분석 플랫폼(SonarQube 등)에 커버리지를 넣어 Quality Gate로 묶음
	- "전체 커버리지 X% 이상" + "신규 코드 커버리지 Y% 이상" 두 축을 같이 봄
	- 도메인이 안전-필수(항공·자동차·의료)면 라인/분기가 아니라 MC/DC까지 요구되고, 도구도 인증된 상용 제품 사용

## 회사 사례 (머지·배포 기준)

| 회사 / 기준                      | 도구                | 머지·배포 기준                                                  | 차단 여부    | 숫자 종류       |
| ---------------------------- | ----------------- | --------------------------------------------------------- | -------- | ----------- |
| Google                       | 자체 인프라 + Critique | 라인 60% / 75% / 90% (acceptable / commendable / exemplary) | X (가이드만) | 목표치         |
| SonarQube 기본 게이트 (Sonar way) | SonarQube         | 신규 코드 커버리지 80% / 중복 3% 이하 / 보안 핫스팟 검토 100%                | O        | 목표치         |
| 우아한형제들 (2020)                | JaCoCo (Gradle)   | 클래스별 라인 80% / 분기 90% / 클래스당 200줄 이하                       | O        | 목표치 (점진 상향) |
| 토스 (2021)                    | JaCoCo (Gradle)   | 100%                                                      | O        | 목표치         |
| 카카오페이                        | SonarQube         | Quality Gate 등급 A (수치 비공개)                                | O        | 목표치         |



# 오픈 소스와 회사의 차이 비교

| 비교 항목      | 오픈 소스                                                                        | 회사                                                                   |
| ---------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 목적         | 기여자·사용자에게 **공개 신뢰**, PR 리뷰 보조                                                | **배포 게이트**, 품질 관리, 인증·감사 증빙                                          |
| 주 측정 기준    | 라인·분기 커버리지                                                                   | 라인·분기 + (안전-필수는) **MC/DC**                                           |
| 임계값 방식     | **패치 커버리지** 중심 (pytest patch 100%, Django diff-cover) / 전체 수치는 `auto`(하락 금지) | **절대값** 중심 (Sonar way 신규 80%, 우아한형제들 클래스 80/90%, 토스 100%) + 신규 코드 별도 |
| 강제 수준      | 경고~머지 차단 프로젝트마다 다름. Django는 명시적으로 "경고일 뿐"                                    | 대부분 **빌드 실패·배포 차단**. 안전-필수는 법적·인증 요구                                 |
| 도구         | 언어 표준 무료 도구 + Codecov/Coveralls (공개 저장소 무료)                                  | SonarQube·JaCoCo 조합, .NET·C++는 상용 도구, 대기업은 자체 인프라(Google)            |
| 비용         | 거의 0원                                                                        | SaaS 인당 과금, 상용 안전-필수 도구는 고가 라이선스                                     |
| 결과 공개      | 배지·대시보드 공개                                                                   | 사내 대시보드, 외부 비공개 (카카오페이처럼 수치 비공개)                                     |
| 제외 규칙      | 벤더 코드·생성 코드·플랫폼별 코드 (Kubernetes deepcopy, Django DB별 코드)                     | 생성 코드·DTO·설정 클래스 (우아한형제들 `Q*`), 단 안전-필수는 제외 자체를 정당화해야 함              |
| 커버리지 개선 방식 | 기여자에게 PR 단위로 요청                                                              | 기준을 **점진적으로 상향**(ratchet)하거나 처음부터 높게 고정                              |
| 대표 수치      | 오픈 소스 Java 프로젝트 대다수 60% 이상 (Hilton 2018)                                     | Google 가이드 60/75/90%, SonarQube 신규 80%, 안전-필수 100% MC/DC             |
