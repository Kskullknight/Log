# 가상화: 물리적으로 존재하지 않는 것을 존재하는 것처럼 보이게 한다.
## 가상화란
- 물리적으로 존재하지 않는 것을 존재하는 것처럼 보이게 하는 기술
- 물리 서버를 늘리지 않고도 필요한 만큼 서버를 늘릴 수 있음
- 반대로 여러 대의 물리 서버를 사용자에게는 하나의 서버처럼 보이게 할 수도 있음

## 가상화의 개념
- 가장 아래에 물리 서버가 있고, 그 위에 호스트 OS, 가상화 소프트웨어, 가상 서버가 차례로 올라가는 구조
	- 물리 서버 => 호스트 OS => 가상화 소프트웨어 => 가상 서버
- 가상화 소프트웨어: 가상 서버를 실행하기 위해 필요한 소프트웨어

## 가상화의 유연성
- 물리적 구성에 얽매이지 않고 환경을 유연하게 구축할 수 있음
	- 물리 서버의 OS는 Windows, 가상 서버의 OS는 Ubuntu로 구성할 수 있음

## 가용성 향상
- 가상 환경마다 따로 백업하고 복구할 수 있음
- 문제가 생기면 직전 상태로 되돌릴 수 있어 시스템의 가용성이 높아짐
- 단, 물리 서버가 멈추면 그 위에서 실행되는 가상 서버도 모두 사용할 수 없음

> [!note]+ 가용성(availability)
>
> - 시스템이 멈추지 않고 서비스를 계속 제공할 수 있는 정도

# 가상화의 종류: 크게 서버 가상화와 네트워크 가상화로 나뉜다.
## 서버 가상화
- 물리 서버를 가상화하는 기술
- 가상화 소프트웨어가 물리 서버의 CPU, 메모리, 디스크를 나누어 각 가상 서버에 할당
- 가상 서버마다 독립된 OS와 애플리케이션을 실행

## 네트워크 가상화
- 물리적 네트워크 구성과 다른 논리적 네트워크를 소프트웨어로 구성하는 기술
- 물리적인 배선이나 장비를 바꾸지 않고 네트워크를 나누거나 합칠 수 있음
	- 설정은 소프트웨어로 제어

## 그 외의 가상화

| 종류       | 내용                                    |
| -------- | ------------------------------------- |
| 스토리지 가상화 | HDD 같은 스토리지 장치를 가상화하는 기술              |
| 데스크톱 가상화 | 데스크톱 환경을 서버에서 실행하고 네트워크를 통해 접근하는 기술 |

# 가상화의 장단점: 복구와 확장이 쉽지만 장애 범위가 넓고 운용이 복잡하다.
## 가상화의 장점
- 가상 서버는 소프트웨어이므로 백업이 쉬움
	- 가상 서버 하나가 하나의 파일로 캡슐화됨
- 복사와 삭제가 쉬움
- 물리적 네트워크 기기 구성에 의존하지 않고 네트워크 구성을 유연하게 바꿀 수 있음
- 네트워크 기기의 관리와 유지보수가 쉬움

## 가상화의 단점
- 서버와 네트워크 관리 외에 가상화에 대한 전문 지식이 필요함
- 도입하고 유지하는 데 비용이 듦
- 물리 서버에 장애가 생기면 그 위의 모든 가상 서버가 영향을 받음

| 구분  | 내용                                      |
| --- | --------------------------------------- |
| 장점  | 쉬운 백업·복구, 쉬운 복사·삭제, 유연한 구성 변경, 쉬운 유지보수 |
| 단점  | 전문 지식 필요, 도입·유지 비용, 물리 서버 장애 시 넓은 영향 범위 |

- 장단점이 뚜렷하므로 시스템의 특성에 맞게 선택해야 함

# 가상화와 클라우드: 클라우드는 가상화 기술로 구축된 인프라나 서비스다.
## 클라우드란
- 가상화 기술로 구축된 인프라나 서비스
- 인터넷을 통해 접근하여 다양한 인프라와 서비스를 이용할 수 있음
- 대표적인 클라우드 서비스로 AWS, GCP, Azure가 있음

### 서비스 모델

| 모델   | 제공 범위       | 사용자 관리 범위        | 예                 |
| ---- | ----------- | ---------------- | ----------------- |
| SaaS | 완성된 애플리케이션  | 사용만 함            | Gmail             |
| PaaS | 애플리케이션의 플랫폼 | 애플리케이션, 데이터      | Google App Engine |
| IaaS | 인프라         | OS, 미들웨어, 애플리케이션 | Amazon EC2        |

> [!note]+ 서비스 모델의 약자
>
> - SaaS: Software as a Service
> - PaaS: Platform as a Service
> - IaaS: Infrastructure as a Service

## 클라우드를 지탱하는 가상화
- 원드라이브(OneDrive)를 예로 들면 스토리지와 서버가 모두 가상화되어 있음

### 스토리지 가상화
- 원드라이브는 사용자마다 5GB를 제공하지만, 실제로 `사용자 수 × 5GB`만큼의 디스크를 미리 확보해 두지 않음
- 미리 준비된 디스크에서 필요에 따라 사용자마다 디스크 공간을 할당
- 물리 디스크 공간과 다른 논리적 영역을 사용자에게 보여줌

| 구분            | 내용                               |
| ------------- | -------------------------------- |
| 사용자에게 보이는 디스크 | 각자 5GB의 디스크가 할당된 것처럼 보임          |
| 실제 디스크        | 공유 디스크이며, 사용자가 5GB를 넘지 않도록 관리만 함 |

- 5GB를 다 쓰지 않은 사용자의 남는 공간도 유효하게 활용할 수 있음

### 서버 가상화
- 사용자가 접속하는 서버도 가상화되어 있음
- 사용자에게는 서버가 하나로 보이지만, 실제로는 여러 대의 서버가 역할을 나누어 맡음
	- 로드 밸런싱(load balancing)

## 클라우드를 지탱하는 분산 처리
- 분산 처리: 처리를 여러 대의 기기에 나누어 맡기는 것
- 작업 처리 속도를 높일 수 있음
- 기기 1대당 부하가 줄어듦

# 클라우드 보안: 안전성은 높지만 리스크도 존재한다.
## 클라우드 보안
- 클라우드는 최신 보안 대책으로 적절하게 관리됨
- 하지만 클라우드가 통째로 탈취되면 호스트 컴퓨터까지 침입당할 가능성이 있음

## 실제로 발생한 취약성의 예
### VENOM
- 2015년 5월 13일 미국 보안 기업 CrowdStrike가 공표한 취약점
- 하이퍼바이저형 가상화와 관련된 취약점
- 클라우드 서비스 전체를 탈취당할 수 있는 매우 위험한 취약점

#### 공격 흐름
1. 공격자가 공격 대상 클라우드 서비스에 일반 사용자로 가입
2. 가상 서버의 관리자로 로그인
3. 가상 플로피 디스크 드라이브의 취약점을 공격
4. 공격 범위가 게스트 OS뿐 아니라 게스트 OS를 탑재한 **호스트 OS**까지 확대
5. 같은 클라우드를 사용하는 모든 사용자가 피해를 입을 수 있음

## 편의성과 보안 문제의 절충
- 온라인 스토리지는 이용 중인 모든 단말이 악성 코드에 감염되기 쉬움
- 높은 수준의 보안 대책 기술을 갖추고 취약점을 항상 숙지해야 함
- 가상화의 편의성 때문에 피해가 더 커질 수 있으므로 최신 취약점 정보를 확인해야 함
