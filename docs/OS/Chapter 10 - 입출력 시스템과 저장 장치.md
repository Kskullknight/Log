## 입출력 시스템
### 입출력 장치와 채널
- 주변 장치는 데이터 전송 속도에 따라 구분할 수 있음
	- 저속 주변 장치: 메모리와 주변 장치 사이에 오고 가는 데이터양이 적어 데이터 전송률이 낮은 장치
		- 키보드
	- 고속 주변장치: 메모리와 주변 장치 사이에 대량의 데이터가 오고 가므로 데이터 전송률이 높은 장치
		- 그래픽 카드, 하드 디스크

- 주변장치들은 메인보드 내의 버스로 연결됨
	- 버스에는 많은 종류의 장치가 연결되어 있어 1개만 사용하면 병목 현상이 발생한다
		- 이를 위해 여러 개의 버스를 묶어서 사용함
	- 데이터가 지나 다니는 하나의 통로를 **채널**이라고 함

- 주변장치는 저마다 속도가 다르기 때문에 채널을 무분별하게 사용하면 문제가 발생한다.
- 모든 주변 장치가 채널을 공유하면 전체적으로 속도가 느려짐
	- 전송 속도가 비슷한 장치끼리 묶어서 장치별로 채널을 할당하여 효율적으로 사용

### 입출력 버스의 구조
#### 초기의 구조
- 초기에는 주변장치가 많지 않고 CPU와 메모리의 속도도 빠르지 않았음
- 모든 장치가 하나의 버스로 연결되어 있음
- CPU가 작업을 진행하다 입출력 명령을 만나면 입출력 장치에서 직접 데이터를 가져옴
	- 이를 폴링(polling) 방식이라고 함
- 폴링 방식을 하면 입출력이 끝날 때까지 다른 작업을 할 수가 없음

#### 입출력 제어기를 사용한 구조
- CPU와 메모리의 성능이 급격하게 발전하고 주변 장치의 종류도 다양해짐
	- 따라서 CPU가 폴링 방식으로 주변 장치를 관리하기 어려워짐
- 모든 입출력을 제어하는 입출력 제어기에 맡기는 구조로 변함
	- 입출력 제어기는 메인버스와 입출력 버스의 2개 채널로 나뉜다.
		- 메인 버스: CPU와 메모리가 사용
		- 입출력 버스: 주변장치들이 사용
	- 입출력 요청이 오면 입출력 관리자가 입출력 장치로부터 데이터를 받아 직접 송신한다.
- 입출력 장치로 인해 CPU와 메모리의 작업이 느려지는 것을 막을 수 있다.

#### 입출력 버스의 분리
- 입출력 제어기 때문에 작업 효율은 높아졌지만 저속 주변 장치 때문에 고속 주변장치의 데이터 전송이 느려지는 문제가 발생함
	- 이 문제를 해결하기 위해서 고속 입출력 버스와 저속 입출력 버스로 분리하여 운영하게 됨
- 채널 선택기를 두어 저속 버스와 고속 버스 사이의 입출력을 관리함
- 그래픽 카드의 성능이 비약적으로 성장하면서 고속 입출력 버스로 감당할 수 없을 만큼 빠르고 커짐
	- 전용 버스를 이용하여 메인 버스에 직접 연결함
	- 그래픽카드 전용 포트인 AGP(Accelerated Graphics Port)에 꽂는다.

### 직접 메모리 접근 (DMA)
- CPU 없이 직접 메모리에 접근할 수 있도록 하는 입출력 제어기에 부여된 권한
	- 입출력 제어기에는 직접 메모리 접근을 위한 DMA 제어기가 있음
- 채널 선택기가 어떤 데이터를 메모리로 보낼지 결정함
	- 전송된 데이터는 DMA 제어기를 거쳐 메모리에 적재됨
	- 메모리에서 주변장치로 데이터를 보낼 때는 DMA를 거쳐 채널 선택기에서 적당한 채널에 전송한다.
- DMA가 도입되면서 CPU의 작업 공간과 DMA의 작업 공간이 섞이는 문제가 발생함
	- 예전: 별도의 입출력 메모리를 둠
	- 요즘: 메인 메모리의 일부를 구분하여 사용
		- 메모리 맵 입출력(MMIO: Memory Mapped I/O)

### 인터럽트
#### 입출력과 인터럽트
- 외부 인터럽트: 주변 장치의 입출력 요구나 하드웨어의 이상 현상을 CPU에게 알려주는 신호
	- 입출력 제어기는 작업을 완료하면 CPU에게 인터럽트를 보냄
	- 네트워크 카드에 새로운 데이터가 도착한 경우
- 인터럽트가 어떤 장치에서 발생했는지 구분하기 위해서 IRQ라는 고유의 인터럽트 번호가 부여됨
	- 인터럽트가 발생하면 CPU는 IRQ를 보고 어떤 장치가 인터럽트를 발생했는지 파악한다.
- 하드웨어 인터럽트
	- 입출력 장치가 아닌 전원 이상이나 기계적인 오류가 발생한 경우 발생하는 인터럽트
- 내부 인터럽트
	- 프로세스의 잘못이나 예상치 못한 문제 때문에 발생
		- 숫자를 0으로 나누기
		- 주소 공간을 벗어난 작업
	- 예외 상황 인터럽트라고도 함
- 시그널
	- 사용자의 의지로 사용자가 직접 발생시키는 인터럽트

#### 인터럽트 벡터와 인터럽트 핸들러
- 인터럽트는 한번에 여러 개가 발생하기도 함
	- 이러한 상황에서 어떤 인터럽트가 발생했는지 파악하기 위한 자료구조로 **인터럽트 벡터**를 사용함

- 인터럽트마다 처리 방법이 다름
	- 인터럽트의 처리 방법을 함수 형태로 만든 것을 인터럽트 핸들러라고 함
	- 인터럽트가 발생하면 인터럽트 핸들러를 호출함
- 인터럽트 벡터에 해당하는 인터럽트 핸들러를 호출할 수 있도록 인터럽트 핸들러가 저장된 메모리 주소가 포인터 형태로 등록되어 있음
	- 사용자가 만든 인터럽트의 경우 사용자가 만든 인터럽트 핸들러를 등록할 수도 있음

### 단일 버퍼와 이중 버퍼
- 버퍼
	- 속도가 다른 두 장치의 속도 차이를 완화하는 역할을 한다.
	- 느린 장치를 통해서 들어오는 데이터를 버퍼에 모아 한번에 이동시킬 수 있다.
	- 입출력 장치의 느린 속도를 버퍼로 보완한다.
- 커널에서도 입출력 장치로 보내야 할 데이터를 버퍼에 담아서 보낸다
	- 커널이 입출력 작업이 완료되기 전에 다른 작업을 진행할 수 있음
	- 예시) 스풀러를 사용하는 프린터

- **단일 버퍼**
	- 하나의 버퍼에 전송과 수신에 모두 사용함
	- 따라서 동시에 작업하기 어려움
- **이중 버퍼**
	- 하나의 버퍼는 담는 용도
	- 하나의 버퍼는 가져가는 용도로 구분하여 사용
	- 동시에 작업이 가능하다

## 저장장치
### 저장 장치의 종류
#### 하드디스크(moving-head hard disk drive)
- 기존에는 테이프 드라이브로 맨 뒤에 있는 데이터를 읽기 위해서 테이프를 끝까지 감아야 했음
	- 이후 원반을 사용한 저장장치로 발전하여 맨 앞이나 맨 뒤에 있는 데이터를 읽는 속도가 거의 비슷해지면서 많은 시스템에서 도입하게 됨

- 메모리를 보조하는 장치라는 의미에서 제2저장장치라고 불린다.
- 단편화 문제가 발생하여 주기적으로 조각 모음을 하여 속도가 저하되는 것을 방지한다.

##### 구조
###### 플래터
- 표면에 자성체가 발려 있어 자기를 이용하여 0과 1의 데이터를 저장함
	- N = 0, S = 1
###### 섹터와 블록
- 섹터
	- 물리적으로 하드디스크의 가장 작은 저장 단위
- 블록 
	- 논리적으로 하드디스크의 가장 작은 저장 단위
	- 블록은 여러개의 섹터로 구성된다.
- 논리적인 단위인 블록마다 주소가 배정됨
- 운영체제는 블록 단위로 하드디스크의 데이터를 송수신한다.
###### 트랙과 실린더
- 플래터에서 회전축을 중심으로 데이터가 기록되는 동일한 동심원상에 있는 섹터의 집합
	- 헤드는 디스크 암에 고정되어 있기 때문에 모든 헤드가 항상 같이 움직인다.
		- 따라서 헤드는 여러 플래터의 같은 위치에 있는 트랙을 동시에 읽거나 쓸 수 있다.
- 개념적으로 여러 개의 플래터에 있는 같은 트랙의 집합을 **실린더**라고 한다.
###### 헤드와 플래터
- 헤드의 수는 데이터가 저장되는 플래터의 표면 수와 같다.
- parking
	- 컴퓨터가 종료될 때 헤드가 플래터의 표면에 흠집을 내지 않도록 데이터가 저장되지 않는 플래터의 맨 바깥쪽으로 이동함
	- 전원 코드를 뽑거나 정전이 되면 파킹되지 않은 상태에서 헤드가 플래터에 붙어버려 배드 섹터가 되어버린다.

#### SSD(Solid State Disk)
- 하드디스크의 느린 속도를 대체하기 위해 개발된 보조 저장장치
- 전원이 없어도 데이터를 저장하는 플래시 메모리로 구성됨
- 메모리를 이용하여 속도가 매우 빠름
- 물리적으로 움직이는 부품이 없어 작고 가벼우며 소음이 없다.
- 하드 디스크에 비해 비싸다
- 기존에는 SATA 방식을 사용했지만 최근에는 NVMe(Non-Volatile Memory Express) 방식의 독자적인 인터페이스를 사용하여 초당 7GB의 데이터 전송 속도를 가짐
- 단편화에 대한 영향이 거의 없다.
	- 오히려 쓰기 횟수가 정해져 있어 조각 모음을 하지 않는 것이 더 좋다.

#### CD
- 하드디스크처럼 원반을 사용하는 저장장치
- 종류
	- CD - 640MB
	- DVD - 4.7GB
	- 블루레이 - 25GB
- 표면에 미세한 홈을 파고 표면에 레이저를 쏴 반사된 빛에 따라 0과 1을 구분함
	- 0 - 홈에 들어가 빛이 반사되지 않음
	- 1 - 표면에 빛이 반사됨
- 레이저를 쏘아 표면을 태워서 미세한 홈을 만든다.

#### CD와 하드디스크의 비교
- 성능 단위
	- 하드디스크: RPM
		- 하드 디스크는 일정한 속도로 돌아감
	- CD: 배속
		- 헤드의 위치에 따라 회전 속도가 달라짐
- 회전 방식
	- 하드디스크: 각속도 일정 방식의 회전
		- 플래터가 항상 일정한 속도로 회전하고 헤드가 움직이므로 일정시간동안 이동한 각도가 같음
		- 섹터
			- 트랙마다 속도가 다르기 때문에 섹터의 크기도 다름
			- 모든 트랙의 섹터 수는 같고 바깥쪽 섹터의 크기가 안쪽 섹터보다 크다.
	- CD: 선속도 일정 방식
		- 어느 트랙에서나 단위 시간당 디스크의 이동거리가 같다.
		- 헤드가 안쪽 트랙에 있을 때는 디스크의 회전 속도를 빠르게 하고 바깥쪽 트랙으로 이동했을 때는 디스크의 회전 속도를 느리게 한다.
		- 섹터
			- 안쪽 트랙보다 바깥쪽 트랙에 더 많은 섹터가 존재함
- 쓰기 위치
	- 하드 디스크: 바깥쪽에서 안쪽으로 데이터가 채워짐
	- CD: 안쪽에서 바깥쪽으로 데이터가 채워짐
		- 데이터 보호 차원에서 주로 만져지는 바깥쪽이 아닌 안쪽부터 데이터를 채운다
### 디스크 장치의 데이터 전송 시간
##### 데이터 전송 과정
1. 탐색 시간(seek time)
	- 헤드가 읽으려는 데이터가 저장된 섹터로 이동하는데 걸리는 시간
2. 회전 지연 시간(rotational latency time)
	- 원하는 섹터를 만날 때까지 플래터가 회전하는데 걸리는 시간
3. 전송 시간(transmission time)
	- 데이터를 읽어 전송하는데 걸리는 시간

=> 데이터 전송 시간 = 탐색 시간 + 회전 지연 시간 + 전송 시간

- 데이터 전송 시간의 대부분은 탐색 시간이 차지하기 때문에 탐색 시간을 최소화하기 위해서 디스크 스케줄링 기법을 사용한다.

## 디스크 스케줄링
- 트랙의 이동을 최소화하여 탐색 시간을 줄이는 데 목적이 있다.
### FCFS 디스크 스케줄링
- 가장 단순한 디스크 스케줄링 방식
- 요청이 들어온 트랙 순서대로 서비스

### SSTF(Shortest Seek Time First) 디스크 스케줄링
- 현재 헤드가 있는 위치에서 가장 가까운 트랙부터 서비스한다.
	- 같은 거리이면 먼저 들어온 트랙을 서비스한다.
- 효율성은 좋지만 아사 현상을 일으킬 수 있다.
	- 헤드가 중간에 위치하면 가장 안쪽이나 가장 바깥쪽에 있는 트랙을 서비스할 확률이 낮아지기 때문이다.
- 일괄 작업 시스템처럼 다른 프로세스에 영향을 주지 않고 빠른 응답 성능을 필요로 하는 서비스에서 사용한다.

### 블록 SSTF 디스크 스케줄링
- SSTF 디스크 스케줄링의 공평성 위배를 어느 정도 해결한 방법
- 큐에 있는 트랙 요청을 일정한 블록 형태로 묶은 후 블록에서
