## 설계 원리
- 설계: 도메인 중심의 분석 결과를 소프트웨어 관점으로 전환하는 과정
	- 로직 설계, 클래스/메서드 설계, UI, 자료구조, DB, 물리적 구조 설계를 포함

- 설계 과정의 기본 원리
	- 추상화: 대표 특징으로 사물을 나타냄
		- 부모 클래스 생성, 유사 클래스를 패키지로 표현
	- 단계적 상세화: 클래스 멤버 제약사항, 메서드 내부 로직 설계 등의 구체화 작업
	- 모듈화: 변경 대처와 확장성을 높임
	- 정보 은닉: 클래스 멤버의 참조 범위 선언 (Public, Private 등)
	- 관심사의 분할: UI, 자료구조 등 관심사를 분리하여 설계

- 세 가지 설계 기법
	- 팩토링: 유사점/차별점에 따라 모듈(클래스)로 분리
		- 일반화(상속): 공통점을 추출하여 상위 클래스 생성
		- 집합(구성): 상호 관련성을 갖는 요소들을 묶음
		- 추상화: 추상/상위 클래스 생성
		- 상세화: 하위 클래스 생성
	- 파티셔닝: 큰 모델을 세부 모델로 나누는 과정
		- 모듈화 개념을 적용하여 서브시스템을 구성
	- 계층화: 시스템 구성 요소를 운영, 사용환경 등을 고려하여 다른 그룹으로 분리
		- Model-View-Controller 아키텍처
			- Model: 메서드(처리 로직)
			- View: UI, 사용자 입력
			- Controller: 입력 해석 후 Model에 전달
		- 3계층 아키텍처
			- 사용자 인터페이스 계층 (Presentation)
			- 처리 로직 계층 (Domain)
			- 데이터 관리 계층 (Persistence)

- 객체지향 방법론 기반 설계 과정
	- 클래스 다이어그램을 패키지 다이어그램으로 작성
	- UI 클래스와 데이터베이스 테이블 생성
	- 배치 다이어그램을 작성하여 패키지를 하드웨어 플랫폼에 할당
	- 구현에 필요한 기술 스펙 정의
## 패키지 다이어그램
- 응집력이 높은 클래스들을 패키지로 묶어 전체 시스템을 상위/서브시스템 수준에서 보여줌
	- 하드웨어 장치에 패키지 단위로 할당
### 패키지 다이어그램 생성
1. 대상물 선정 (도메인 클래스 다이어그램)
2. 관련성 높은 것들을 그룹핑
	- 일반화, 집합 관계의 클래스를 하나의 패키지로
3. 패키지에 명칭 부여
4. 패키지 간 관계 부여 (주로 연관 관계)
5. 다이어그램의 프레임으로 완성
### 계층화된 아키텍처 생성
- 3계층 아키텍처

| 계층     | 다른 이름                          | 포함 클래스                            |
| ------ | ------------------------------ | --------------------------------- |
| HCI 계층 | Human Computer Interaction, Presentation | UI 클래스                            |
| PD 계층  | Problem Domain, Business Logic | 도메인 클래스 (UI 및 DM 클래스 생성의 기반)      |
| DM 계층  | Data Manipulation, Persistence | 데이터 클래스                           |
## 자료 구조 설계
- 3계층 아키텍처의 하위 층(DM 계층) 설계 시 파일/데이터베이스 테이블을 설계
	- PD 계층의 클래스 정보를 바탕으로 자료구조 정의

- 설계 가이드라인
	- 휘발성 변수 제거
	- 모든 클래스를 하나의 테이블로 매핑
		- 멤버 변수 → 컬럼
		- 멤버 함수 → 프로그램 함수 / 저장형 프로시저
	- 일대일 관계: key로 정의
	- 다대다 관계: 새로운 테이블을 생성하여 관련 클래스 연결
	- 일반화 관계: 하위 클래스 테이블에 key 추가

- 이상현상 해결을 위해 정규화 수행
- 성능 향상을 위해 인덱스 테이블 구성
## 사용자 인터페이스 설계
### 인터페이스 설계 절차
#### 1. 사용 시나리오 개발
- 사용자 입장에서 시스템이 사용되는 방식을 기술
	- 각 시나리오 스텝은 유스케이스 시나리오 스텝과 연결
#### 2. 인터페이스 구조 설계
- 시나리오 스텝을 블록 다이어그램 형태로 도식화
- 윈도우 네비게이션 다이어그램 작성
#### 3. 인터페이스 템플릿 개발
- 사용자 제시 스타일의 화면 레이아웃 설계 (2~3개)
#### 4. 인터페이스 프로토타입 개발
- 템플릿을 기반으로 프로토타입 개발
#### 5. 인터페이스 평가
- 개발팀 내부 평가
- 사용자 평가
- 시나리오 기반 평가
### 인터페이스 클래스 설계
- 모든 도메인 클래스에 대한 인터페이스 클래스 정의
	- 멤버 함수가 모두 private이면 구성하지 않음
- 스테레오타입 `<<interface>>`로 표현
	- 메서드는 UI 메뉴와 연결
## 물리 구조 설계
- 소프트웨어 컴포넌트(패키지)를 어떤 구조의 하드웨어 플랫폼에 배치할지 설계
### 배치 다이어 그램 작성
- 모든 패키지를 플랫폼에 할당

- 클라이언트-서버 운영 모델
	- 서버 기반: 처리, 데이터 저장이 서버에서 진행
	- 클라이언트 기반: 클라이언트에서 처리, 서버에서 데이터 저장
	- Thin Client-Server: 클라이언트는 디스플레이만 수행
	- Thick Client-Server: 클라이언트가 처리 능력을 가져 작업 분산

- 고려 요소
	- 개발 비용
	- 개발 용이성
	- 보안 통제
	- 확장성 (Scalability)
### 기술 환결 명세
- 각 하드웨어의 스펙과 하드웨어 및 지원 소프트웨어의 세부사항을 명세
- 명세 완료 후 구현 단계로 진행
